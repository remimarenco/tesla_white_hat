# Research Documentation

This directory contains research notes, methodologies, and findings from Tesla security research.

## Contents

- **[methodology.md](methodology.md)**: Research methodology and best practices
- **findings/**: Security findings and observations (following responsible disclosure)
- **notes/**: General research notes and observations

## Organization

Research documentation should be:
- **Dated**: Include timestamps on all entries
- **Detailed**: Provide enough context for reproducibility
- **Safe**: Exclude exploit code or sensitive details
- **Ethical**: Follow responsible disclosure guidelines

## Adding Research

When adding new research:

1. Follow the methodology outlined in [methodology.md](methodology.md)
2. Use the research session template
3. Document safety considerations
4. Report vulnerabilities to Tesla first
5. Sanitize any sensitive information

## Security Findings

⚠️ **Important**: Any security vulnerabilities discovered must be:
1. Reported to Tesla (security@tesla.com or via Bugcrowd)
2. Not publicly disclosed until patched
3. Documented in sanitized form (no exploit code)
4. Coordinated with Tesla's security team

See [../SECURITY.md](../../SECURITY.md) for full disclosure policy.
